# Audit bug NutriScan, 30 Oktober 2026

## Perbaikan

1. Simpan yang sudah masuk database tetapi respons/refresh gagal sebelumnya bisa dicoba ulang dengan ID baru, menghasilkan catatan ganda. Identitas draft sekarang tetap, konfirmasi simpan dipisahkan dari refresh, dan respons hilang direkonsiliasi memakai ID/isi yang sama.
2. Revisi edit sebelumnya dibaca dari daftar riwayat terbaru, bukan revisi saat catatan dibuka. Revisi sekarang dipertahankan pada draft agar perubahan bersamaan tidak tertimpa diam-diam.
3. Penggantian foto saat simpan/decode belum selesai bisa mencampurkan keadaan draft. Pemilihan foto, buka catatan dan simpan kini dijaga selama operasi terkait berlangsung.
4. Pembacaan riwayat sebelumnya menunggu pembersihan foto. Pembersihan kini dijadwalkan setelah respons, dengan budget delapan detik dan antrean tahan-gagal. SDK Storage mempunyai timeout koneksi/request.
5. Penanganan origin/cookie memahami HTTPS proxy Vercel. Header forwarded protocol hanya dipercaya dalam runtime Vercel; origin browser tetap harus sama.
6. Batas API scan/migrasi sebelumnya bisa melebihi payload Vercel. Scan maksimum 3 MiB dan migrasi lima catatan per batch. Respons HTML 413/502 ditampilkan sebagai pesan yang bisa dipahami.
7. Batas delapan scan sebelumnya memakai satu kunci bersama untuk semua sesi pada instance. Kunci sekarang per pemilik sesi. Ini belum rate limit terpusat lintas instance.
8. Contoh GEMINI_MODEL berisi nama model yang bukan ID Gemini. Contoh dikosongkan agar memakai default; konfigurasi rahasia lokal tidak diubah. Runtime package dibatasi Node 22.x yang diuji.
9. Runner tes API sekarang memulangkan exit code gagal yang benar, menyimulasikan Host/proxy HTTPS melalui HTTP transport yang mempertahankan Host, dan memeriksa Secure cookie serta foto privat tanpa kode dalam URL.

## Verifikasi

- 48 tes otomatis lulus, termasuk respons simpan hilang, refresh gagal, target/porsi/tanggal berbeda, payload dan cleanup yang dibatalkan.
- TypeScript dan kompilasi produksi lulus. Pengujian produksi dilakukan dengan Webpack dan worker serial di salinan audit bersih karena sandbox Windows menolak junction Turbopack dan sebagian pembuatan direktori paralel. Pengaturan worker khusus audit tidak dipasang ke proyek pengguna; build default Turbopack belum berhasil diverifikasi dalam sandbox ini.
- Uji API terhadap Neon/Storage dengan dua sesi sintetis lulus: kode akses, origin proxy HTTPS, Secure cookie, katalog v4, profil, foto privat upload/baca/hapus, logout/resume, isolasi pemilik, konflik revisi, konfirmasi hapus, hapus satu/semua, dan anti-resurrection migrasi. Seluruh fixture dibersihkan.
- Uji SQL transaksi rollback lulus. Hanya baris milik UUID sesi uji yang diakses/dibersihkan.
- npm audit dependency produksi: nol kerentanan terlapor. Pemindaian 54 file sumber awal tidak menemukan pola credential hardcoded; .env.local tidak ditampilkan atau disalin.
- Daftar model Gemini berhasil diakses; konfigurasi lokal gemini-3.5-flash-lite tersedia. Tidak memanggil generateContent dan tidak menguji akurasi scan foto baru.

## Batas yang masih berlaku

Sesi anonim berbasis cookie belum akun lintas perangkat/domain. Profil/riwayat localhost tidak otomatis dapat dibuka di URL Vercel meskipun tetap tersimpan di Neon. UI hanya memuat 200 laporan terakhir; ringkasan di luar jangkauan tersebut belum lengkap. Rate limit/cache masih per instance. Porsi, resep dan sumber gizi estimasi perlu diperiksa. Audit ini tidak menyatakan seluruh kemungkinan bug sudah tidak ada.

Deployment tidak dijalankan. Panduan manual sudah disiapkan terpisah dan tidak mengubah layanan hosting.
